# NB 输入法：改字记录（第一版）

2026-10-29。PM 想知道每次语音输入以后，自己在输入框里把字改成了什么，给以后的主动优化攒数据。第一版只记录，不做任何自动修改。

## 拍的板

- 只在本机记录「识别结果 → 我改完的样子」，和录音对上。
- 设置里可以关（「通用 › 文字 › 记下我改了哪些字」，默认开）。
- 密码框不读。

## 做法（`Edits.swift`）

- 粘贴后 0.4 秒用辅助功能接口读当前焦点输入框的全文，按光标位置（对不上就从后往前找）找到刚粘进去的那段字，记下它前后各 16 个字当锚点。
- 之后每秒读一次，两个锚点中间就是这段字现在的样子。焦点离开这个输入框、又按下快捷键、锚点找不到了（比如聊天框发出去被清空）、或者过了 2 分钟，就停下，按最后一次读到的记。
- 读不到全文时，对前台应用设一次 `AXManualAccessibility`（Electron 应用默认不开辅助功能树），0.3 秒后再读一次；还读不到就跳过，日志里每个应用提一次，带上焦点控件的角色，方便以后看覆盖面。
- 记录：数据文件夹 `edits/edits.jsonl`，一行一条：时间、应用、录音文件名、时长、识别结果（润色前）、粘进去的、改完的、改没改。改过的那几条把录音另存到 `edits/`（最多 300 段），不会跟着「最近 20 段」被删。
- 历史页里改过的那条多一行「改成了：…」。
- 调试：`NBIME --edit-test <刚输入的字> [--seconds N]`，假装刚把这段字粘进了焦点输入框，盯 N 秒后把结果写进日志，不进记录。要用 `open -g -n -a` 启动装好的 app（辅助功能权限认的是 app，不认从终端直接跑的程序）。
- 设置窗口加高到 520，「通用」页多了一行放得下。

## 实测

- 文本编辑：粘进「我想将这些内容上传到我的 Dropbox。」后改成「……iCloud 里。」，记成 Dropbox → iCloud 里。先改成「李总」再清空整个输入框（模拟发出去），按清空前的「李总」记。
- 历史里 200 条，Claude 121 条、微信 44 条，这两个是重点。PM 各说了一句再改字：微信记成「中午吃什么呢？」→「中午吃什么？」，Claude 记成「测试一遍」→「测试一次」，没改的两句记成没改。两个都能读到（Claude 是 Electron；是不是靠 `AXManualAccessibility` 那一下才读到的，日志里没单独记）。
- ClawChat Test 读不到（当时焦点可能不在输入框里，日志补了焦点控件的角色再看）。

## 已知的不足

- 粘贴后接着往后写的字，也会算进「改完的样子」里（锚点在后面，新写的字落在两个锚点中间）。分析时要分开看。
- 锚点只有 16 个字，长文档里同样的 16 个字出现两次时可能对错位置。
- 焦点离开就停，切走再切回来改的不算。
