## 附加题：agent 照着仓库能不能帮它的用户搭起来

PM 的问题：agent 读了我们的上下文，能不能帮它的用户在几乎没有依赖的情况下搭一个能用的输入法？

### 评估（假装刚拿到仓库的 agent，只看 README、`server/README.md`、`docs/` 和代码）

能编译，搭不起来。卡在这几处：

- **整个仓库默认用户有一台 Windows 显卡机。** README 的「想自己跑一遍」第一步就是「在一台有显卡的机器上装 CapsWriter」，`server/README.md` 通篇是 ITX。CapsWriter-Offline 的服务端官方只保证 Windows（README 里写了 macOS 不支持），没有显卡机的用户没有路可走，文档里也没提别的办法。
- **默认配置指向原作者的机器。** `Settings.swift` 里 `tunnelHost = "winrig"`、`serverHost = "itx-1.local"`，装好一启动就去 ssh 一台不存在的机器。README 只说「到设置里填你的地址」，没说「不要 ssh、直连本机」要把 `tunnelHost` 清空，也没列 `config.json` 的键。
- **ssh 免密登录的前提没写。** C 路线要 Windows 开 OpenSSH 服务、配公钥、`~/.ssh/config` 起名字，`server/README.md` 默认这些都有。
- **润色只有 Windows 的部署办法**，没说接口是 OpenAI 兼容的 `/v1/chat/completions` + `/health`，Mac 上 `brew install llama.cpp` 就能起。
- **没有给 agent 的验收步骤。** `--test-file` 能用 `say` 生成的音频自测整条识别路径（`AVAudioFile` 读 aiff 没问题），`--polish-test` 能测润色，但 README 没把它们串成「每一步怎么确认」。
- **人必须亲手做的事没单独列出来**：麦克风、辅助功能、本地网络权限，按快捷键（模拟按键会被系统丢掉）。agent 不知道哪里该停下来交给用户。
- 小的：需要 macOS 26（胶囊用了 `NSGlassEffectView`）、界面只有中文、没签名时每次重编要重新给辅助功能权限。README 里都提了，但散在各处。

### 实测：没有显卡机时的路

- **macOS 26 自带的 `SpeechTranscriber` 能做离线中文识别。** 这台 M5 / macOS 26.6.2 上 `supportedLocales` 30 个，含 `zh_CN`、`zh_TW`、`zh_HK`、`yue_CN`、`ja_JP`；`zh_CN`、`zh_TW` 已经装好。用 `say -v Tingting` 合成「下周一把灯塔计划新的设计稿发给产品经理，顺便看一下登录页的接口为什么返回五百」，转写 0.38 秒，得到「……顺便看一下登陆业的接口为什么返回 500。」，错一个词。`SFSpeechRecognizer(zh-CN).supportsOnDeviceRecognition` 也是 true。
- **系统的 `FoundationModels`（端侧大模型）** 在这台 M5 上返回 `deviceNotEligible`，没试出润色效果。
- Mac 上起 `llama-server`、拿别的模型包一个 CapsWriter 协议的服务，都没实测，引导里标了。

### 补了什么

- `docs/setup-with-agent.md`：写给 agent 的引导。先一次问清楚用户的五件事，三条路（A 只用 Mac、系统自带识别；B Mac 本机跑识别服务；C 局域网显卡机）怎么选，然后按「编译 → 识别 → 配置 → 润色 → 交给用户」的顺序，每一步写了怎么确认做好了、日志里该看到什么、卡住时对照哪一行，最后是常见的坑。A 路线写清了接在哪（实现一个和 `ASRClient` 接口一样的 `LocalASR`）和要用的系统 API。
- 三份 README 的「把它当上下文用」开头加了一段「一键提示词」，用户整段复制给自己的 agent，指向那份引导；阅读顺序表里加了这一行；「想自己跑一遍」的标题注明这是照原作者的环境跑，没有显卡机就交给 AI 照引导做。
- 没改客户端代码：A 路线的本地识别引擎留给用户的 agent 按引导去写。
