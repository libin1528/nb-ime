# 念一串名字，模型顺着热词表往下背

2026-11-02。PM 说一段 41.5 秒的话，后半段在列举 agent：「比如说我们把 Grokbot、Dot、缪斯这一类作为个人 agent，然后再增加一类开发的，就是 Claude Code、Codex、OpenClaw……」。粘进去的是「比如说我们把 Grokbot、Wan3、develop-ui、session、Eros、集卡、Grokbot、小柚、Agent、集卡、Grokbot、小柚。」，后面 15 秒的话全没了。几分钟后另一段 17 秒的「生产力 agent 就是 Claude Code、Codex，甚至包括像 Cursor 等等」也变成「生产力 agent 就是 develop-ui、session、joe、集卡、Grokbot、小柚、Agent、集卡、Grokbot、小柚。」

## 原因

- 念的是一串用顿号隔开的名字，头一个正好是热词（Grokbot）。热词是用逗号连成一串送给模型的，模型就顺着这张表往下背：不从第一个热词开始，顺序是乱的，常带重复，有时一直背到被截断（重放时见过 146 个）。
- 预览是对的。预览也带热词，但每 2 秒一段，模型没有地方往下背。
- 以前的两道检查都对不上：`echoedHotwords` 只拦整句都是热词的，`strippedEcho` 只拦从第一个热词起、按原顺序抄在开头的。

## 试过的

两段录音各认 4 次，`seg_duration` 60 秒：

| 热词怎么送 | 41 秒那段 | 17 秒那段 |
|---|---|---|
| 逗号隔开（现状） | 3 次背热词表 | 4 次 |
| 不带热词 | 0 | 0 |
| 写成一句「本段语音可能提到这些词：……」 | 0 | 4 次 |
| 一行一个 | 3 次 | 0 |
| 空格隔开 | 2 次 | 0 |

换哪种格式都没法让两段都对。把分段改短也不稳：41 秒那段，20 秒一段 3 次都对，15 秒一段 3 次里有 2 次错。

## 改法

`Settings.hotwordRun`：完整结果里有一串只隔着标点的热词，连着 5 个及以上，或者 3 个及以上里有同一个词出现两次，就算顺着热词表背了。这时把同一段录音**不带热词**再认一次，用这次的结果，后面照常走正负号、一定替换、按读音换回热词。日志记「热词连成一串（N 个）：…，不带热词重认」和「重认 …：不带热词「…」」。

- 整句都是热词的不走这里，还是走原来的倒序复核；倒序复核回来的结果也不再查。
- 规则先在全部历史上过了一遍：日志里 1974 条结果和改字记录，只命中这次的几条和 10-30 那条开头抄热词表的（那条重认也能认对），没有误伤。
- 代价是多认一次：17 秒的录音多 1.2 秒左右，41 秒的多 2.5～3.5 秒。只有命中的那几次才会多。

## 实测

装好后用 `--test-file` 两段录音各重放 5 次：10 次都命中，重认后的结果都是 PM 原话，例如「比如说我们把 Grobot、Out、Muse 这一类作为个人 agent，然后再增加一类开发的，就是 Chat Codex、Open Cloud、Cloud Code 这一类。」「生产力 agent 就是 code codex，甚至包括像 cursor 等等。」

没解决的：不带热词时 Grokbot 常认成「Grobot」。按读音换回热词只认拼得成拼音的词，这个换不回来。10-30 也有一次带着热词认成「Grobot」的，可以考虑加一定替换 `Grobot=Grokbot`。
